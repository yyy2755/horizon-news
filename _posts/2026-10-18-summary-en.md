Parser combinators are a foundational technique in functional programming and compiler construction, and this post's animated approach makes the concept more accessible to newcomers. This approach is popular in functional languages like Haskell (e.g., Parsec) and is often contrasted with parser generators, which produce a parser from a formal grammar file. Regex-based tokenizers sit at the simpler end of the spectrum, handling tokenization but not recursive structure.

## [Java's Sealed Classes and Exhaustive Pattern Matching Explained](https://neilmadden.blog/2026/04/24/java-sealed-classes-and-exhaustive-pattern-matching/) ⭐️ 6.0/10

A blog post by Neil Madden explains how Java's sealed classes (introduced in Java 17) and exhaustive pattern matching (finalized in Java 21) work together to enable compile-time exhaustiveness checking in switch expressions. This combination represents a significant evolution in Java's type system, allowing developers to model closed hierarchies and have the compiler verify that all possible subtypes are handled, which improves API design and code safety. Sealed classes use the `sealed` modifier and a `permits` clause to restrict which classes can extend them, and when combined with records and pattern matching in switch, the compiler can enforce exhaustiveness without a default clause.

hackernews · hnisjafx40 · Oct 18, 14:47 · [Discussion](https://news.ycombinator.com/item?id=50141579)

**Background**: Java 17 introduced sealed classes (JEP 409) to give developers finer-grained control over inheritance, allowing a class or interface to explicitly list its permitted subclasses. Pattern matching for switch (JEP 441) became a permanent feature in Java 21, enabling case labels with type patterns and guards. Together, these features let the compiler check that a switch handles all possible subtypes of a sealed hierarchy, a concept familiar from languages like Kotlin and Scala.

## [Inline rendering with document.currentScript](https://simonwillison.net/2026/Oct/17/document-currentscript/) ⭐️ 6.0/10

Lean Rada demonstrated a technique where an inline <script> element uses document.currentScript to replace itself with rendered content, such as the current year. This trick offers a lightweight, dependency-free way to embed dynamic content directly in HTML, which could be useful for simple static sites or prototyping without a full templating engine. **Background**: document.currentScript is a read-only property of the Document interface that returns the <script> element whose script is currently being processed, or null if not applicable. It is not available in JavaScript modules, where import.meta provides similar context. The replaceWith() method is a newer DOM API that replaces an element with a set of Node or string objects, simplifying DOM manipulation compared to older methods.
