## [Rust 1.100 stabilizes never type, custom allocators, and dependency cooldowns](https://blog.rust-lang.org/2026/11/12/Rust-1.100.0/) ⭐️ 8.0/10

Rust 1.100.0 was released on November 12, 2026, stabilizing the never type, custom allocators, dependency cooldowns (minimum publish age configuration), and unused dependency warnings in Cargo. Additionally, cargo install now uses the existing lockfile in the .crate tarball by default, making --locked a no-op. This milestone release brings long-awaited features that improve type system expressiveness, memory management flexibility, and supply chain security, impacting all Rust developers. The community response highlights both enthusiasm for these additions and ongoing concerns about compile times. The never type (!) is now stable for use in function return types and other contexts, custom allocators allow fine-grained control over memory allocation, and dependency cooldowns let projects ignore crate versions published more recently than a configured threshold unless already in Cargo.lock. Unused dependencies are now reported by default with a warning.

**Background**: Rust is a systems programming language focused on safety and performance. The never type represents computations that never complete, custom allocators enable specialized memory strategies, and dependency cooldowns help mitigate supply chain attacks by delaying adoption of new crate versions. Cargo is Rust's package manager and build system.

Security researcher Mehmet Ince published a detailed write-up showing how a 22-year-old type confusion vulnerability in PostgreSQL (CVE-2026-6460) can be chained into remote code execution. The exploit involves creating a composite type, altering one of its fields, and reading the value back to trigger memory corruption. This research highlights the potential severity of long-standing type confusion bugs in PostgreSQL, which could affect countless deployments if exploited. It also sparks debate about whether such vulnerabilities should be classified as RCE or privilege escalation, impacting how organizations prioritize patches. The exploit chain achieves code execution as the operating system user running the database, but it requires an authenticated database session, meaning the attacker must already have valid credentials. The vulnerability affects PostgreSQL versions before 18.6, 17.11, 16.15, 15.19, and 14.24, and was fixed in a batch of 52 security patches.

Remote code execution (RCE) typically refers to an attacker executing arbitrary code on a target system, often without authentication, while privilege escalation involves gaining higher permissions from an existing foothold.
